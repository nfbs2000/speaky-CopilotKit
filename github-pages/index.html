Mothership과 CopilotKit은 실행 원천 소유권을 명확히 해야 공존할 수 있다.

Mothership은 기존 자체 에이전트 실행/runtime surface다. CopilotKit은 FrontendTool, RunHandler, AG-UI UI/runtime이다. Mothership native stream과 evidence를 CopilotKit이 대신 소유하면 권한, 질문, tool result, 완료 판정이 깨진다. 연결의 핵심은 committed Mothership event를 AG-UI로 바꾸는 projector다.

Mothership 우선 기존 Mothership runtime이 run/turn/native stream을 소유한다.
projection은 그 다음 CopilotKit은 Mothership이 투영한 AG-UI event만 받는다.
evidence가 판정 완료 판정은 Mothership evidence/readback 기준이다.
Native HITL standard interrupt -> resume[] -> permission.reply로 같은 native turn을 재개한다.

한 줄 규칙

Mothership native stream은 원천이다. 기존 Mothership runtime이 먼저 받는다. CopilotKit adapter의 핵심은 저장된 event의 AG-UI projector다. 승인은 같은 request ID의 native permission.reply로 돌아간다.

Mothership baseline

Mothership이 여기서 의미하는 것

이 문서의 Mothership은 이미 자체 에이전트 실행 방식, session, stream 소비, tool result, permission/question loop, evidence 저장을 가진 기존 runtime이다. CopilotKit은 이 실행 원천을 대체하지 않고 AG-UI projection과 UI/runtime layer로 붙어야 한다.

공개 문서에는 내부 파일 경로나 비공개 구현명을 쓰지 않는다. 기준은 "기존 Mothership이 먼저 실행하고 먼저 관찰한다"는 ownership이다.

Mothership이 소유한다 기존 agent session과 후속 turn session reuse provider/native stream의 첫 소비와 event persistence permission/question pending state와 같은 session으로 되돌리는 응답 loop backend tool call/result 원본과 agent 의사결정용 결과 turn completion, interruption, evidence archive, readback
CopilotKit에 넘기면 안 된다 provider/native stream의 첫 소비자 역할 기존 agent session id 생성/재사용 판단 permission/question을 browser-local fake approval로 처리하는 흐름 tool result를 CopilotKit renderer 성공 표시로 대체하는 흐름 assistant text만으로 완료 판정하는 흐름 Mothership DB/evidence 없이 CopilotKit runner store만 durable record로 쓰는 흐름

Mothership common core

Mothership의 공통 부분

Mothership의 공통부는 특정 UI, card, chat bubble이 아니다. 기존 Mothership 방식에서 반복되는 핵심은 native 실행을 시작하고, 그 실행의 원본 event와 증거를 잃지 않고, 사람이 보는 화면으로 투영하는 control kernel이다.

실행 identity runId, turnId, provider/native session id 후속 turn이 같은 agent session을 재사용하는 규칙 새 session은 명시적인 새 run에서만 만드는 lifecycle
native event ledger provider/native stream 수신 raw event identity와 correlation id 보존 timeline, transcript, evidence archive
interaction loop permission/question pending state pending interaction에 대한 approve/deny/answer callback 응답 뒤 같은 native session에서 계속 흐르는 stream
tool result integrity backend/domain tool call과 result 원본 기존 agent가 다음 행동을 결정할 수 있는 result 보존 renderer 표시가 원본 result를 대체하지 않는 규칙
completion evidence assistant text가 아니라 turn completion/readback으로 판정 interruption, failure, timeout을 성공처럼 만들지 않는 규칙 Opik/trace evidence는 검증된 receipt가 있을 때만 success
projection adapters Mothership UI, transcript, status projection CopilotKit AG-UI bridge는 이 projection 중 하나 projection은 source of truth가 아니다

경계 비교

역할 비교

이 구조에서 CopilotKit은 실행 권한의 주인이 아니다. CopilotKit은 agent UI와 AG-UI runtime layer다. 기존 에이전트 실행의 control plane은 Mothership에 남아 있어야 한다.

영역 Mothership CopilotKit
주요 역할 기존 에이전트 실행과 evidence를 소유하는 runtime/control plane agent 상호작용을 위한 UI/runtime framework
native 실행 소유자 agent session, backend tool, permission/question 응답 등록된 AG-UI agent에 실행을 위임
stream 원천 기존 Mothership native/provider event SSE로 흐르는 AG-UI BaseEvent stream
저장 소유자 Mothership DB, native timeline, tool ledger, evidence readback AgentRunner thread/event store
완료 판정 관찰된 native stream, tool result, evidence readback RUN_FINISHED 같은 AG-UI lifecycle projection

의도적으로 선택할 것

구성 선택

"CopilotKit이 가로채면 Mothership이 못 받는다"는 걱정은 CopilotKit이 Mothership보다 upstream에 있을 때 맞다. Mothership을 upstream에 두면 CopilotKit이 소비하는 것은 의도적으로 공개한 AG-UI projection이다.

선택 사항: CopilotKit Runtime을 추가하는 배치

Browser -> CopilotKit Runtime -> HttpAgent -> Mothership AG-UI endpoint -> existing Mothership native session.

이중 라우트가 맞다. CopilotKit 공식 문서의 runtime-backed AG-UI 연결 방식과 같은 계열이며, runtime routing, server-side middleware, auth 경계를 CopilotKit 쪽에 두고 싶을 때 쓴다.

단, 이 구성이 Mothership-first의 유일한 권장안은 아니다. Runtime은 AG-UI projection을 프록시할 뿐이고, Mothership native stream과 evidence의 source of truth가 되면 안 된다. 

const runtime = new CopilotRuntime({
  agents: {
    mothership: new HttpAgent({
      url: process.env.MOTHERSHIP_AGUI_URL!,
    }),
  },
  runner: new InMemoryAgentRunner(),
});

기본 검증: 직접 연결 Mothership agent

Browser -> HttpAgent -> Mothership AG-UI endpoint. 이 agent는 CopilotKit Runtime을 우회한다. Mothership 실행 소유권을 가장 단순하게 보존하는 projection-only 구성이다.

adapter 계약을 가장 먼저 검증할 때는 CopilotKit의 direct path인 selfManagedAgents로 연결할 수 있다. 대신 인증, 권한, CORS, rate limit, replay는 Mothership endpoint가 직접 책임진다. 

<CopilotKit
  selfManagedAgents={{ mothership: mothershipAgent }}
>
  <CopilotChat agentId="mothership" />
</CopilotKit>

정리

먼저 Mothership committed envelope를 AG-UI로 바꾸는 adapter와 native HITL 왕복을 검증한다. selfManagedAgents 직접 연결은 그 계약을 확인하는 가장 짧은 배치다. Runtime의 인증, middleware, routing이 실제로 필요해진 뒤에만 같은 adapter 앞에 CopilotKit Runtime을 추가한다. 배치 선택이 projector 필요성을 바꾸지는 않는다.

선행 조건 direct/runtime 어느 배치든 Mothership AG-UI projector가 먼저 있어야 한다. permission resume는 같은 native request의 reply command로 돌아가야 한다.
Runtime 사용 조건 runtime-backed 구성은 공식적으로 지원된다. Runtime은 인증, middleware, routing, Enterprise 기능의 경계다. 그 기능이 필요한 경우 검증된 adapter 앞에 추가한다.
SSE 이중 프록시 현실 Runtime은 upstream SSE를 raw passthrough하지 않는다. HttpAgent가 AG-UI event를 소비하고 Runtime이 다시 SSE로 인코딩한다. 따라서 두 hop 모두 timeout, abort, reconnect, buffering 검증이 필요하다.
Mothership 기본안 기존 실행 소유권이 중요하면 selfManagedAgents 직접 연결을 먼저 본다. 이 경우 CopilotKit Runtime은 빠지고 Mothership endpoint가 보안과 replay를 맡는다. projection-only UI가 목표라면 이 경로가 더 단순하다.
공존 불가 조건 CopilotKit Runtime과 Mothership이 같은 continuation/persistence를 동시에 소유하려 하면 깨진다. raw native event가 반드시 브라우저까지 보존돼야 하면 AG-UI projection은 부족하다. 이 경우 CopilotKit은 renderer만 쓰거나 통합하지 않는 선택도 가능하다.

런타임 custom runner tee

Browser -> CopilotKit Runtime -> custom AgentRunner -> SDK/Mothership. CopilotKit이 agent를 실행해야 하지만 Mothership도 모든 AG-UI event를 관찰해야 할 때 쓰는 구성이다.

이 방식은 기본적으로 projection-level AG-UI event를 관찰한다. provider-native chunk까지 필요하면 SDK adapter 단계에서 raw tee를 별도로 넣어야 한다. 

class MothershipRunner extends InMemoryAgentRunner {
  override run(request) {
    // event를 Mothership에 persist/tee한 뒤 위임한다.
    return super.run(request);
  }
}

위험한 구성

Browser -> CopilotKit Runtime -> BuiltInAgent/direct SDK adapter -> provider SDK stream.

Mothership이 실행을 통제하거나 검증해야 한다면 이 구성은 쓰면 안 된다. Mothership이 stream 경로 밖에 있으므로 single-consumer SDK stream을 놓칠 수 있다. 명시적인 tee를 추가하거나 실행을 Mothership 뒤로 옮겨야 한다. 

// 위험: CopilotKit이 SDK call을 소유한다.
const runtime = new CopilotRuntime({
  agents: {
    default: new BuiltInAgent({ model: "..." }),
  },
});

상관관계 계약

ID 매핑

CopilotKit thread 변경은 Mothership이 native run에 매핑하기 전까지 UI-level event일 뿐이다. browser reconnect 때문에 새 provider session이 우발적으로 생기면 안 된다.

agentIdMothership 화면/agent 표면. 보통 mothership으로 고정한다.
threadId하나의 Mothership runId에 매핑한다.
runIdMothership turnId 또는 correlation id에 매핑한다.
messageIdnative message correlation에 매핑하고 browser에는 sanitized id만 노출한다.
provider session idMothership 내부 runtime session id다. browser가 소유하지 않는다.

Mothership에서 AG-UI로

스트림 변환 계약

Mothership AG-UI endpoint는 RunAgentInput을 받고 text/event-stream을 반환한다. provider chunk를 그대로 흘리는 것이 아니라 Mothership event를 AG-UI event로 변환한다.

Mothership 관찰값 AG-UI event 계열 규칙
turn accepted RUN_STARTED AG-UI run마다 한 번만 emit하고 stable id를 포함한다.
assistant text delta TEXT_MESSAGE_CHUNK 또는 start/content/end 빈 delta는 emit하지 않는다.
tool call과 args TOOL_CALL_START, TOOL_CALL_ARGS toolCallId와 JSON-stable args를 보존한다.
tool result 관찰 TOOL_CALL_END, TOOL_CALL_RESULT tool 성공 여부는 Mothership evidence로 판정한다.
state snapshot 또는 delta STATE_SNAPSHOT, STATE_DELTA host secret이 아니라 sanitized status만 노출한다.
native permission/question pending RUN_FINISHED with outcome.type = "interrupt" useInterrupt가 결정을 받고 resume[]로 같은 native interaction을 재개한다.
native error 또는 completion RUN_ERROR, RUN_FINISHED Mothership completion 기준을 만족한 뒤에만 emit한다.

frontend tool과 native interrupt 구분

followUp: false는 native permission 해결책이 아니다

followUp은 CopilotKit frontend tool handler가 끝난 뒤 agent를 자동으로 다시 실행할지 정하는 옵션이다. OpenCode에서 발생한 permission/question은 frontend tool이 아니므로 이 옵션으로 우회하지 않고 AG-UI standard interrupt를 사용한다.

Native permission/question

  1. Mothership이 native event와 pending request를 먼저 저장한다.
  2. projector가 RUN_FINISHED outcome: interrupt를 emit한다.
  3. useInterrupt가 승인·거절·답변 UI를 렌더링한다.
  4. resolve(payload)가 RunAgentInput.resume[]를 보낸다.
  5. adapter가 같은 request ID에 permission.reply/question.reply를 호출한다.

실제 CopilotKit frontend tool

  1. agent가 앱에 등록된 frontend tool을 호출한다.
  2. browser handler가 앱 동작을 실행하고 tool result를 반환한다.
  3. agent가 result를 읽고 답해야 하면 기본 follow-up을 유지한다.
  4. 후속 agent 실행이 불필요한 app tool에서만 followUp: false를 선택한다.
  5. 이 경로를 native provider permission으로 위장하지 않는다.
Native HITL은 useInterrupt로 렌더링한다

사용자 결정은 새 prompt가 아니다. CopilotKit에서는 resume payload이고, Mothership에서는 같은 run/turn/native request를 재개하는 SDK reply다. 

useInterrupt({
  render: ({ interrupt, resolve }) => (
    <PermissionReview
      request={interrupt}
      onApproveOnce={() => resolve({ decision: "once" })}
      onApproveAlways={() => resolve({ decision: "always" })}
      onReject={() => resolve({ decision: "reject" })}
    />
  ),
});

// adapter: RunAgentInput.resume[]
// -> MothershipService.respondPermission(...)
// -> OpenCode client.permission.reply(...)
Native provider HITL AG-UI standard interrupt와 resume[]를 사용한다. followUp은 설정하지 않는다.
Frontend tool CopilotKit agent가 tool result를 읽어야 하면 기본 follow-up을 유지한다. 후속 run이 불필요할 때만 followUp: false를 쓴다.
거절과 중단 native reject는 resolve({ decision: "reject" })로 명시한다. cancel()이나 Stop은 native abort와 별도 계약이다.

결론: followUp: false는 frontend tool의 후속 실행 옵션일 뿐이며, Mothership native permission/question의 HITL 왕복에는 관여하지 않는다.

tool 권한

host tool을 frontend tool로 등록하지 않는다

filesystem, process, git mutation, renderer direct bridge 같은 실제 실행 도구는 native Mothership capability다.

좁은 domain command만 노출한다 request_mothership_change open_mothership_run show_mothership_evidence
Mothership gate 뒤에 둔다 host filesystem/process/git mutation product-specific direct bridge destructive tool permission workspace path, role/tier gate

사람 승인 루프

permission은 Mothership session state다

CopilotKit은 standard interrupt를 받아 approval UI를 렌더링한다. 사용자의 resolve()는 resume[]로 adapter에 돌아오고, adapter는 Mothership의 원래 pending request에 응답한다. 최종 호출은 새 채팅 메시지가 아니라 OpenCode SDK의 permission.reply(requestID, once|always|reject)다.

프로토콜 run과 native turn을 구분한다

interrupt에서 첫 AG-UI SSE는 종료되고 사용자 결정 후 resume AG-UI 요청이 시작된다. 그 사이에도 Mothership은 같은 OpenCode session과 pending turn을 유지한다. adapter는 resume를 새 Mothership turn이나 새 OpenCode session으로 만들면 안 된다.

저장과 보안

실제 작업의 기준은 Mothership evidence다

CopilotKit runner persistence는 UI thread replay에는 유용하다. 하지만 Mothership native 작업의 유일한 durable record가 되면 안 된다.

분리 저장

raw provider/native event는 Mothership에 저장한다. AG-UI projection event는 CopilotKit runner나 browser state에 둘 수 있다.

ID 상관관계 유지

CopilotKit threadId, AG-UI runId, Mothership runId, Mothership turnId, provider session id 매핑을 보관한다.

endpoint 보호

모든 Mothership AG-UI request를 인증하고 threadId -> runId 접근 권한을 server-side에서 검사한다.

browser state 정제

host path, token, environment variable, raw tool payload, billing internal을 UI state에 투영하지 않는다.

운영 배포 기준

통합 체크리스트

CopilotKit과 Mothership이 안전하게 통합됐다고 말하기 전에 이 항목을 확인한다.

  1. Mothership이 RunAgentInput을 받는 AG-UI endpoint를 하나 제공한다.
  2. Mothership이 기존 native/provider stream을 CopilotKit보다 먼저 소비한다.
  3. 모든 AG-UI threadId가 stable Mothership runId에 매핑된다.
  4. AG-UI run/resume 시도가 Mothership turn에 매핑되며 interrupt 전후의 여러 AG-UI run이 같은 turn을 재개할 수 있다.
  5. permission/question은 RUN_FINISHED outcome: interrupt로 투영한다.
  6. useInterrupt의 resume[]는 원래 Mothership pending interaction에 되돌린다.
  7. once/always/reject와 question answers가 같은 request ID의 native reply로 전달된다.
  8. native permission/question에 followUp: false frontend tool 우회를 사용하지 않는다.
  9. backend/native tool은 CopilotKit frontend tool로 직접 등록하지 않는다.
  10. browser-visible state는 sanitized 상태다.
  11. runtime-backed deployment를 선택했다면 Mothership을 HttpAgent로 등록한다.
  12. self-managed deployment를 선택했다면 Mothership endpoint를 직접 인증한다.
  13. production 전에 reconnect/replay 동작을 정의한다.
  14. 완료 판정은 assistant text가 아니라 Mothership evidence에서 한다.
