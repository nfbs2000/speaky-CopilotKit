M AG-UI Projection Adapter Mothership x CopilotKit
경계 문서 소유권 경계 현재 프로젝터 어댑터 계약 구현 순서 외부 링크
결론 확인된 상태 현재 프로젝터 소유권 경계 어댑터 계약 이벤트 매핑 ID와 수명주기 권한과 질문 SSE와 유실 CopilotKit 연결 구현 순서 검증 기준 근거

source-read decision · 2026-08-03

켜는 옵션은 없다. Mothership과 CopilotKit 사이에 AG-UI projection adapter를 만든다.

Mothership은 OpenCode native session과 native stream의 소유자로 남는다. 어댑터의 핵심은 Mothership에 저장이 끝난 event를 AG-UI event로 바꾸는 projector다. native HITL의 역방향만 AG-UI resume를 원래 OpenCode permission.reply로 전달한다. CopilotKit은 OpenCode를 다시 실행하거나 native SSE를 다시 소비하지 않는다. CopilotKit 연결 방식은 어댑터 계약과 검증이 끝난 뒤 배포 경계에 맞춰 결정한다.

실행 소유자 Mothership이 run, turn, OpenCode session, permission/question, abort를 소유한다.
필수 구현 committed envelope -> AG-UI events[] projector와 resume[] -> permission.reply.
HITL 계약 RUN_FINISHED outcome: interrupt, useInterrupt, resume[]를 사용한다.
금지 CopilotKit용으로 두 번째 OpenCode session이나 두 번째 native stream 소비자를 만들지 않는다.

evidence status

현재 확인된 것과 아직 만들지 않은 것

이 문서는 구현 완료 보고서가 아니다. Education Shell과 CopilotKit 소스를 대조해 어댑터의 정확한 경계를 결정한 설계 문서다. 확인된 사실과 제안을 구분한다.

소스로 확인됨 Mothership이 OpenCode native session을 만들고 같은 session에 후속 turn을 보낸다. OpenCode native event를 MothershipStreamEvent로 바꾸는 projector가 이미 있다. raw evidence와 stream envelope를 저장하고 permission/question의 native request ID를 보존한다.
아직 구현되지 않음 Mothership committed envelope를 AG-UI BaseEvent로 바꾸는 두 번째 projector. standard interrupt와 resume[]를 native reply로 연결하는 production adapter. CopilotKit dependency와 연결 방식의 제품 구성.
현재 판정 결론은 과거와 같다. 별도 실행기가 아니라 projection adapter를 만들어야 한다. 아래 구현과 실제 HITL 왕복 테스트 전에는 “공존 구현 완료”라고 말하지 않는다.

current source audit

첫 번째 프로젝터는 이미 있다

Education Shell은 OpenCode raw SSE를 그대로 UI에 던지지 않는다. native event를 Mothership 표준 stream event로 투영하고, seq가 있는 envelope로 저장한다. 새 작업은 이 원장을 다시 해석해 AG-UI로 투영하는 두 번째 projector다. 

OpenCode native SSE
  -> OpenCodeProcess raw event
  -> existing OpenCode -> Mothership projector
  -> persisted MothershipStreamEvent / envelope / seq
  -> missing Mothership -> AG-UI projector
  -> CopilotKit
현재 Education Shell 구성 상태 의미
OpenCodeProcess 구현됨 SDK client, global native SSE, session과 native permission/question reply를 소유한다.
projectOpenCodeStreamEvent 구현됨 permission.asked -> permission.requested 등 native event를 Mothership event로 바꾼다.
writer, ledger, replay, recovery 구현됨 저장 후 발행, seq replay/gap 판정, pending native interaction과 session 복구를 제공한다.
MothershipEnvelope -> BaseEvent[] 미구현 CopilotKit이 소비할 production AG-UI projector다.
resume[] -> permission.reply/question.reply 미구현 CopilotKit 버튼 결정을 같은 native request와 turn으로 돌려보내는 HITL bridge다.
제거된 과거 어댑터는 정답이 아니다

Git 이력의 CopilotKit provider leaf sidecar는 요청마다 copilot-leaf-opencode-* 별도 session을 시작하고 결과 text를 반환한 synthetic verification이었다. Mothership의 기존 run/turn/native permission을 투영하지 않았고, 현재 production 코드에서도 제거됐다.

single ownership boundary

바뀌면 안 되는 소유권 경계

Mothership은 이미 OpenCode를 실행하는 상위 런타임이다. CopilotKit을 붙인 뒤에도 native 실행의 단일 소유자는 Mothership이어야 한다. AG-UI는 원장이 아니라 UI를 위한 projection이다. 

OpenCode native session
        |
        | SDK/native events
        v
Mothership runtime
  - run / turn / native session
  - permission / question / abort
  - raw evidence / stream ledger
        |
        | committed envelope
        v
Mothership AG-UI Projection Adapter
  - identity mapping
  - lifecycle + message projection
  - replay / live / gap handling
        |
        | AG-UI events
        v
CopilotKit UI
단일 진실 원천

native 실행 상태, 완료 판정, permission request, tool evidence의 기준은 Mothership ledger다. AG-UI stream이 끊겨도 Mothership run과 evidence는 독립적으로 복구할 수 있어야 한다.

공존이 아닌 구성

CopilotKit 쪽 adapter가 OpenCode session을 새로 만들거나 OpenCode native SSE를 별도로 구독하면 두 실행 원천이 생긴다. 이 경우 session, permission, abort, completion, evidence가 갈라진다.

adapter contract

어댑터의 핵심은 projector다

정방향은 저장이 완료된 Mothership envelope를 AG-UI event로 바꾸는 projector다. 역방향은 standard interrupt의 resume를 Mothership interaction command로 전달한다. OpenCode SDK를 별도 실행하거나 raw native SSE를 다시 소비하지 않는다. 

interface MothershipAgUiAdapter {
  run(input: RunAgentInput): AsyncIterable<AgUiEvent>;
  abort(aguiRunId: string): Promise<void>;
}

project(envelope, projectionState): AgUiEvent[]

if (input.resume) {
  validateInterruptIdentity(input.resume);
  dispatchToMothershipNativeInteraction(input.resume);
}
명령 변환 RunAgentInput을 Mothership run 시작 또는 같은 run의 다음 turn 명령으로 변환한다. resume[]는 새 turn이 아니라 원래 pending interaction command로 전달한다.
이벤트 투영 committed envelope를 AG-UI lifecycle, text, activity, state와 interrupt event로 바꾼다. native event와 evidence를 AG-UI 결과에서 역생성하지 않는다.
전송 복구 ledger replay와 live subscription을 연결하고 seq gap을 탐지한다. 중복 전송은 stable event/message ID로 멱등 처리한다.
adapter = projector의 정확한 뜻

공개 event를 만드는 핵심은 작고 결정적인 projection 함수다. 다만 AG-UI는 양방향이므로 wrapper는 run/turn identity, replay/live, abort와 interrupt resume dispatch를 함께 가진다. 실행 소유권을 가져오는 두 번째 agent runtime이라는 뜻은 아니다.

projection mapping

AG-UI로 무엇을 어떻게 투영하는가

lifecycle은 Mothership command 결과와 turn 완료 판정을 기준으로 만들고, 텍스트는 stable message ID 하나에 누적한다. native backend tool을 frontend tool로 위장하지 않는다.

Mothership 기준 사건 AG-UI projection 규칙
turn 생성과 native 실행 접수 완료 RUN_STARTED 원본 event 이름을 추측하지 않고 실제로 생성된 turn ID와 연결한다.
assistant message 시작 TEXT_MESSAGE_START Mothership message key로 stable AG-UI message ID를 만든다.
assistant delta append TEXT_MESSAGE_CONTENT 이미 투영한 길이를 기억하고 새 delta만 보낸다.
assistant final replace reconcile 후 TEXT_MESSAGE_END 최종 전체 본문을 다시 delta로 보내 중복시키지 않는다.
native tool/subagent/status ACTIVITY, CUSTOM 또는 state CopilotKit이 실행한 frontend tool처럼 표현하지 않는다.
permission/question pending RUN_FINISHED with outcome.type = "interrupt" useInterrupt가 UI를 렌더링하고 resume[]로 원래 interaction을 재개한다.
Mothership turn 완료 RUN_FINISHED terminal evidence와 pending interaction 해소가 확인된 뒤에만 보낸다.
실패 또는 명시적 abort RUN_ERROR 또는 중단 상태 SSE 연결 종료만으로 native abort를 추정하지 않는다.

identity and lifecycle

CopilotKit의 run과 Mothership의 run은 같은 단위가 아니다

CopilotKit의 한 번의 agent run은 Mothership의 한 turn에 해당한다. 장기 대화 thread는 같은 Mothership run과 같은 OpenCode native session을 계속 사용한다.

CopilotKit threadId Mothership runId에 매핑한다.
CopilotKit runId AG-UI 요청 시도에 해당한다. interrupt 전후의 여러 run이 같은 Mothership turn에 매핑될 수 있다.
Mothership runId 장기 OpenCode native session과 연결한다.
Mothership seq replay와 projection audit의 canonical 순서로 사용한다.
잘못 매핑하면 생기는 문제

CopilotKit의 요청마다 Mothership run이나 OpenCode session을 새로 만들면 후속 turn 문맥이 사라진다. 반대로 장기 Mothership run 종료만 기다렸다가 RUN_FINISHED를 보내면 CopilotKit의 한 요청이 끝나지 않는다.

native interaction bridge

permission과 question은 투영하되 소유권은 옮기지 않는다

Mothership은 이미 pending request ID, turn ID, native session을 알고 있다. projector는 이를 AG-UI standard interrupt로 내보낸다. CopilotKit UI가 받은 결정은 resume[]로 adapter에 돌아오고, adapter는 원래 Mothership command를 호출한다. 

native permission/question event
  -> Mothership stores raw event + envelope + pending checkpoint
  -> adapter emits RUN_FINISHED { outcome: { type: "interrupt" } }
  -> CopilotKit useInterrupt renders approve/deny/answer controls
  -> resolve(payload) sends RunAgentInput.resume[]
  -> adapter validates interruptId -> runId/turnId/native requestId
  -> Mothership respondPermission/respondQuestion
  -> OpenCode permission.reply/question.reply on the same native turn
사용자 결정 Mothership command OpenCode native reply
한 번 승인 respondPermission(allowed=true, always=false) permission.reply(..., "once")
항상 승인 respondPermission(allowed=true, always=true) permission.reply(..., "always")
거절 respondPermission(allowed=false) permission.reply(..., "reject")
followUp: false와 useHumanInTheLoop 경로가 아니다

followUp은 frontend tool handler 이후 agent 자동 재실행 옵션이다. OpenCode가 발생시킨 native permission은 frontend tool이 아니므로 standard interrupt/resume를 쓴다. 거절도 cancel()이 아니라 resolve({ decision: "reject" })로 보내 native provider에 명시적 reject를 전달한다.

승인 메시지가 아니라 native reply다

adapter는 승인 문장을 새 prompt로 보내거나 새 OpenCode session을 시작하지 않는다. 원래 request ID를 사용해 SDK client.permission.reply()를 호출한다. CopilotKit에는 새 AG-UI resume 요청이 생기지만 Mothership에서는 같은 run과 같은 turn이 계속된다.

replayable delivery

SSE는 무손실이 아니라 유실 탐지와 재생을 보장한다

socket은 끊길 수 있고 서버는 브라우저 reducer 적용까지 증명할 수 없다. 따라서 기준은 Mothership envelope가 연속 seq로 저장되고, adapter가 그 seq에서 다시 투영할 수 있는지다.

저장 후 전송 raw event, stream event, envelope commit이 끝난 뒤 live subscriber에 publish한다. 저장되지 않은 native chunk를 먼저 AG-UI로 보내지 않는다.
replay/live race 차단 먼저 live subscriber를 등록해 buffer한다. DB replay를 보낸 뒤 replay 마지막 seq보다 큰 buffered event만 flush한다.
gap은 숨기지 않음 gap, expired, invalid cursor면 정상 delta를 계속 보내지 않는다. full readback 또는 snapshot 복구로 전환한다.
중복 허용, 결과는 멱등 재전송은 at-least-once로 가정한다. stable event/message ID와 projection watermark로 같은 내용을 중복 적용하지 않는다.
delta와 replace 조정 assistant delta와 최종 전체 message를 독립적으로 전송하지 않는다. message별 projection state로 최종 본문을 reconcile한다.
abort와 disconnect 구분 SSE disconnect는 전송 중단이고 native abort는 명시적 명령이다. CopilotKit의 Stop 동작만 Mothership abort로 전달한다.

connection is secondary

CopilotKit 연결 방식은 어댑터 다음에 결정한다

Runtime, custom agent, HttpAgent는 어댑터를 CopilotKit에 노출하는 방식이다. 이 선택이 Mothership의 native event를 AG-UI로 투영해야 한다는 결론을 바꾸지 않는다.

배치 조건 연결 방식 판정
Education Shell 내부에서 함께 실행 custom agent 또는 in-process bridge가 adapter를 호출 추가 upstream SSE 없이 같은 adapter를 재사용할 수 있다.
Mothership을 별도 프로세스·서비스로 공개 HttpAgent가 Mothership AG-UI endpoint를 호출 HTTP/SSE transport와 인증, timeout, reconnect를 추가 검증한다.
CopilotKit Runtime 사용 Runtime agent가 같은 adapter에 연결 지원되는 배치지만 Mothership ledger를 canonical source로 유지한다.
판단 순서

먼저 adapter의 command, projection, replay, interaction 계약을 완성한다. 그 다음 Education Shell 배포 경계에 맞춰 in-process 또는 HTTP transport를 선택한다. transport 선택을 공존 원리나 필수 옵션으로 설명하지 않는다.

implementation sequence

어댑터 중심 실행 순서

endpoint나 CopilotKit UI부터 만들지 않는다. 저장 완료 envelope를 입력으로 하는 projector와 identity/lifecycle 계약을 먼저 고정한 뒤 transport와 UI를 연결한다.

  1. P0: Mothership committed envelope fixture를 만들고 project(envelope, state) -> AG-UI events[] projector를 구현한다.
  2. P1: threadId -> runId, AG-UI run/resume attempt -> Mothership turn, message key와 projection watermark 저장 계약을 구현한다.
  3. P2: Mothership event writer의 DB commit 이후 full envelope를 발행하는 subscriber bus를 추가한다.
  4. P3: subscriber 선등록, replay, buffered live flush 순서로 replay/live bridge를 구현한다.
  5. P4: permission/question을 AG-UI standard interrupt로 투영하고 resume[]를 원래 native request의 Mothership reply command로 연결한다.
  6. P5: once/always/reject/question 답변의 native reply, stale/duplicate/unauthorized resume를 검증한다.
  7. P6: CopilotKit Stop을 Mothership abort로 전달하고 단순 SSE disconnect와 구분한다.
  8. P7: adapter 계약이 통과한 뒤 배포 경계에 맞춰 in-process bridge 또는 AG-UI HTTP/SSE endpoint를 선택한다.

proof before claim

공존 완료라고 말하기 위한 검증

화면에 글자가 스트리밍되는 것만으로는 충분하지 않다. 같은 native session과 evidence가 유지되고, 끊김과 pending interaction에서도 복구되는지를 실제 통합 테스트로 확인해야 한다.

세션 연속성 같은 CopilotKit thread의 여러 요청이 같은 Mothership run과 OpenCode session을 사용하는지 확인한다.
메시지 정확성 delta + final replace에서 누락·중복 없이 최종 assistant message가 일치하는지 확인한다.
reconnect mid-stream disconnect 후 마지막 watermark에서 replay/live가 이어지는지 확인한다.
gap 복구 seq gap, expired cursor, 중복 replay가 정상 delta로 숨겨지지 않는지 확인한다.
interaction RUN_FINISHED outcome: interrupt가 렌더링되고 resume가 원래 request와 같은 native turn으로 돌아가는지 확인한다. once/always/reject와 question answer가 정확한 permission.reply/question.reply로 매핑되는지 확인한다.
중단 CopilotKit Stop은 native run을 abort하고, 단순 네트워크 끊김은 native run을 임의 종료하지 않는지 확인한다.
현재 표현 한계

위 테스트가 실제 Education Shell과 CopilotKit 통합 환경에서 통과하기 전에는 “공존한다”가 아니라 “Mothership 소유권을 보존하는 공존 설계가 확정되었다”라고 표현한다.
