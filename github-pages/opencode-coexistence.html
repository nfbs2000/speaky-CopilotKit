경계 문서 provider 방식 현재 Mothership 변경안 외부 링크
결론 CopilotKit provider Deep Agents 판정 Mothership 현재 구조 맞물리는 지점 공존 topology Mothership 변경안 OpenCode 지원 시나리오 구현 순서 근거

source-read decision

OpenCode를 CopilotKit에 그냥 넘기면 위험하다. 하지만 Mothership이 OpenCode adapter가 되면 공존 가능하다.

CopilotKit provider 통합의 공통점은 provider 이름이 아니다. 핵심은 provider native stream을 AG-UI event로 바꾸는 adapter 경계다. 현재 Mothership은 이미 OpenCode native stream, run/turn, permission/question, evidence를 소유한다. 따라서 Mothership을 CopilotKit 뒤로 밀지 말고, Mothership이 OpenCode-backed AG-UI endpoint가 되어야 한다.

공존 가능 Mothership이 native stream의 첫 소비자이고 CopilotKit은 AG-UI projection만 소비할 때.
가장 쉬운 길 selfManagedAgents -> HttpAgent -> Mothership AG-UI endpoint.
위험한 길 CopilotKit Runtime이 OpenCode session을 직접 새로 만들고 Mothership이 옆에서 관찰만 하는 구성.
필수 스위치 Mothership bridge frontend tool은 followUp: false.

CopilotKit provider pattern

다른 provider 코드에서 보이는 공통 패턴

CopilotKit이 여러 provider를 지원하는 방식은 대부분 같다. provider별 SDK/native event를 직접 UI에 노출하지 않고, adapter가 AG-UI event stream으로 바꾼다. CopilotKit UI와 Runtime은 그 AG-UI event만 처리한다.

provider 계열 CopilotKit 쪽 연결 의미 Mothership에 주는 힌트
LangGraph Platform LangGraphAgent LangGraph stream을 AG-UI event로 변환한다. OpenCode도 native stream을 AG-UI로 투영하는 adapter가 필요하다.
LangGraph FastAPI LangGraphHttpAgent 이미 AG-UI를 말하는 외부 endpoint에 HTTP/SSE로 붙는다. Mothership도 AG-UI endpoint가 되면 같은 패턴으로 붙는다.
ADK, Pydantic AI, Agno, Strands 등 HttpAgent provider 서버가 AG-UI endpoint를 제공하고 CopilotKit은 일반 HTTP agent로 소비한다. 가장 현실적인 Mothership 경로는 generic HttpAgent다.
CrewAI 전용 AG-UI client 또는 HttpAgent 전용 wrapper가 있어도 본질은 외부 agent endpoint를 AG-UI로 읽는 것이다. OpenCode 전용 wrapper가 생겨도 실행 소유권은 따로 판단해야 한다.
핵심

CopilotKit이 원하는 것은 provider 이름이 아니라 AG-UI contract다. HttpAgent는 request body로 RunAgentInput을 보내고, 응답으로 text/event-stream AG-UI SSE를 기대한다.

주의

CopilotKit Runtime을 경유하면 upstream AG-UI SSE를 raw passthrough하지 않는다. Runtime runner가 event를 소비하고 저장/관찰한 뒤 다시 SSE로 발행한다. 이것은 지원되는 구조지만 Mothership의 canonical stream은 아니다.

Deep Agents

Deep Agents는 별도 OpenCode 해법이 아니다

Deep Agents 문서를 보면 agent 자체는 createDeepAgent로 만들지만, CopilotKit 연결은 결국 LangGraphAgent 또는 LangGraphHttpAgent를 사용한다. 즉 Deep Agents는 별도 전송 계층이 아니라 LangGraph/AG-UI 계열 위에 올라간 provider guide다.

도움 되는 점 frontend tool, context, state, interrupt를 agent framework middleware로 넣는 예시를 준다. Mothership bridge tool 설계에 참고할 수 있다.
도움 안 되는 점 OpenCode native session 소유권 문제를 자동으로 해결하지 않는다. Mothership 대신 CopilotKit이 OpenCode를 실행하는 구조가 되면 충돌은 그대로다.
Mothership 적용 Deep Agents를 베끼기보다 provider adapter 패턴을 베낀다. 즉 OpenCode native stream을 Mothership 내부에서 AG-UI로 투영한다.

Mothership current shape

현재 Mothership 구현과 비교

현재 Mothership은 이미 OpenCode-backed runtime surface다. 실행을 시작하고, 같은 native session에 후속 turn을 보내고, permission/question을 원래 pending interaction으로 되돌리고, raw/native evidence와 사람이 보는 stream projection을 분리한다.

영역 현재 Mothership CopilotKit provider 방식 판정
실행 시작 run/turn을 만들고 OpenCode native session을 시작한다. RunAgentInput을 agent adapter에 보낸다. Mothership facade가 RunAgentInput을 run/turn 명령으로 변환하면 맞는다.
후속 turn 같은 native session에 message를 보낸다. 같은 threadId로 agent를 다시 run한다. threadId -> Mothership runId 매핑이 필요하다.
stream native stream을 먼저 소비하고 저장한 뒤 stream envelope로 투영한다. AG-UI event stream을 소비한다. 이미 중간 projection 계층이 있으므로 AG-UI projector를 추가하면 된다.
permission/question pending request ID를 보존하고 원래 session에 reply한다. HITL/custom event/frontend tool로 UI 왕복을 만든다. UI는 CopilotKit이 렌더해도 reply endpoint는 Mothership이어야 한다.
완료 판정 native evidence/readback으로 turn 완료를 판정한다. RUN_FINISHED event를 UI lifecycle로 쓴다. RUN_FINISHED는 Mothership completion 이후에만 emit한다.
replay stream envelope replay와 evidence archive가 있다. connect나 runner store가 UI replay를 담당한다. Mothership replay가 canonical이고 CopilotKit replay는 projection cache다.

fit analysis

이미 맞는 부분

Mothership은 CopilotKit provider adapter에 필요한 핵심 재료를 이미 갖고 있다. 문제는 실행기가 없는 것이 아니라, AG-UI facade가 아직 명시적인 product boundary로 분리되어 있지 않다는 점이다.

  1. OpenCode native stream의 첫 소비자가 Mothership이다.
  2. run과 turn의 stable identity가 있다.
  3. 후속 turn이 같은 native session에 들어간다.
  4. permission/question pending state가 run/turn/session과 묶인다.
  5. stream envelope와 replay cursor가 있다.
  6. raw evidence와 UI projection이 분리되어 있다.
아직 빠진 것

CopilotKit이 직접 소비할 수 있는 RunAgentInput -> AG-UI SSE endpoint가 필요하다. 기존 replay만으로는 live SSE가 부족하므로, record writer 또는 stream ledger 뒤에 live subscriber를 붙여야 한다.

하면 안 되는 것

CopilotKit frontend tool로 native/backend tool을 그대로 재등록하면 안 된다. 그러면 tool 실행 성공 여부와 evidence source가 CopilotKit UI state로 밀린다. native tool은 Mothership/OpenCode 경계 뒤에 두고, CopilotKit tool은 bridge command만 맡긴다.

coexistence topology

공존 가능한 topology

공존의 기준은 단순하다. OpenCode native session은 하나만 있어야 하고, 그 session의 lifecycle과 evidence는 Mothership이 소유해야 한다.

권장 기본안: self-managed Mothership agent

Browser의 CopilotKit UI가 HttpAgent로 Mothership AG-UI endpoint에 직접 붙는다. CopilotKit Runtime은 빠지고, Mothership endpoint가 인증, 권한, replay, abort를 직접 책임진다. 

const mothershipAgent = new HttpAgent({
  url: "/mothership/agui",
});

<CopilotKit selfManagedAgents={{ mothership: mothershipAgent }}>
  <CopilotChat agentId="mothership" />
</CopilotKit>

왜 이게 기본안인가

SSE hop이 하나 줄고, CopilotKit runner replay와 Mothership replay가 덜 겹친다. Mothership이 이미 OpenCode native stream을 소유하므로 이 경로가 가장 단순하다.

지원 가능안: CopilotKit Runtime bridge

CopilotKit Runtime을 반드시 써야 한다면 Runtime의 agent를 HttpAgent -> Mothership AG-UI endpoint로 둔다. 이 구조는 CopilotKit이 지원하는 provider 통합 방식과 맞다. 

Browser
-> CopilotKit Runtime
-> HttpAgent
-> Mothership AG-UI endpoint
-> OpenCode-backed Mothership runtime

운영 검증 조건

이 경로는 이중 SSE proxy다. upstream과 downstream timeout, buffering, abort, reconnect, replay cursor가 모두 검증되어야 한다. 검증 전 기본안으로 두지 않는다.

충돌 구성: CopilotKit이 OpenCode를 직접 실행

CopilotKit Runtime 뒤에 OpenCode direct adapter를 붙여 새 native session을 만들고, Mothership이 별도 surface로 남으면 공존이 아니다. 실행 원천이 둘이 된다. 

Browser
-> CopilotKit Runtime
-> direct OpenCode adapter
-> OpenCode native session

Mothership
-> separate run/session/evidence

깨지는 지점

Mothership이 upstream stream을 먼저 받지 못한다. permission/question reply, tool result, run completion, evidence archive가 CopilotKit 쪽 lifecycle과 분리되어 race한다.

Mothership changes

Mothership을 어떻게 바꾸면 되는가

변경의 방향은 OpenCode 실행기를 새로 만드는 것이 아니다. 현재 Mothership runtime 위에 AG-UI facade를 추가하고, CopilotKit에서 들어오는 request를 Mothership 명령과 stream replay/live subscribe로 연결한다.

1. AG-UI facade endpoint POST /mothership/agui 같은 endpoint를 둔다. 입력은 RunAgentInput, 출력은 text/event-stream AG-UI event다. 이 endpoint가 Mothership start/send/abort/replay를 호출한다.
2. stable identity mapping threadId는 Mothership runId에 매핑한다. AG-UI runId는 Mothership turnId 또는 correlation id에 매핑한다. browser가 임의 id로 native session을 만들지 못하게 server-side auth를 둔다.
3. stream envelope -> AG-UI projector Mothership stream envelope를 AG-UI BaseEvent로 변환한다. assistant text는 TEXT_MESSAGE_*, status는 STATE_SNAPSHOT 또는 ACTIVITY로 보낸다. RUN_FINISHED는 Mothership completion 이후에만 emit한다.
4. live subscribe 추가 현재 replay cursor만으로는 run 중 SSE가 부족하다. event writer 뒤에 subscriber bus를 붙여 DB append와 동시에 AG-UI stream에도 push한다. 새 subscriber는 먼저 replay를 받고 그 다음 live event를 받는다.
5. abort propagation 브라우저 또는 HttpAgent abort signal을 Mothership abort(runId)로 연결한다. 중간 Runtime bridge를 쓰면 Runtime request abort도 Mothership abort까지 전달되어야 한다. 단순 SSE close와 native abort를 혼동하지 않는다.
6. bridge frontend tools permission approve, question answer, send turn 같은 bridge command만 CopilotKit tool로 둔다. 각 bridge tool은 followUp: false를 사용한다. native/backend tool 자체는 CopilotKit frontend tool로 재등록하지 않는다.
권장 event mapping

turn.started는 RUN_STARTED, assistant delta/message는 TEXT_MESSAGE_START/CONTENT/END, pending permission/question은 CUSTOM 또는 activity/state로 보낸다. native tool event는 CopilotKit이 실행한 tool처럼 보이면 안 되므로 기본은 activity/custom이다. 실제 CopilotKit renderer가 필요한 일부 도구만 통제된 TOOL_CALL_* projection을 허용한다.

가장 중요한 불변식

AG-UI event는 projection이다. Mothership의 raw/native evidence, permission request, tool result, completion 판정은 AG-UI event에서 역생성하지 않는다. AG-UI가 끊겨도 Mothership run은 evidence 기준으로 복구되어야 한다.

OpenCode support scenario

CopilotKit이 OpenCode를 직접 지원하면 쉬워지는가

쉬워질 수 있다. 단, 그 OpenCode 지원이 어디서 native session을 소유하는지에 따라 결론이 달라진다.

OpenCode 지원 형태 공존성 Mothership 선택
CopilotKit용 OpenCodeAgent가 직접 native session을 생성 낮음 Mothership이 실행 원천이어야 한다면 직접 사용하지 않는다.
OpenCodeAgent가 외부 session factory 또는 stream owner를 주입받음 높음 Mothership session/stream owner를 주입해 adapter만 재사용한다.
OpenCode AG-UI server adapter가 별도 endpoint로 제공됨 중간 그 endpoint를 Mothership 안에 넣거나 Mothership 앞단에서 통제한다.
Mothership이 자체 AG-UI facade를 구현 높음 현재 구현과 가장 잘 맞는다. official adapter가 생기면 projector 일부만 교체한다.
정리

OpenCode 지원이 생기면 쉬워지는 부분은 event mapping과 transport glue다. 하지만 session ownership은 자동으로 해결되지 않는다. Mothership을 유지하려면 official OpenCode adapter도 Mothership 아래에서 실행하거나, Mothership의 session/stream owner를 주입받는 형태여야 한다.

implementation sequence

실행 순서

한 번에 Runtime bridge까지 가지 말고, Mothership-first direct path를 먼저 검증한다. 그 다음 필요할 때만 CopilotKit Runtime을 중간에 넣는다.

  1. P0: Mothership stream envelope를 AG-UI event로 바꾸는 pure projector를 만든다.
  2. P1: POST /mothership/agui가 저장된 replay를 SSE로 반환하게 만든다.
  3. P2: live subscriber bus를 붙여 run 중 event가 CopilotKit UI에 실시간으로 흐르게 한다.
  4. P3: threadId -> runId, runId -> turnId 매핑과 접근 권한을 저장한다.
  5. P4: permission/question bridge UI와 frontend tool을 붙이고 모두 followUp: false로 둔다.
  6. P5: abort/reconnect/replay gap 테스트를 만든다.
  7. P6: self-managed direct path가 안정된 뒤에만 CopilotKit Runtime bridge를 추가 검토한다.
  8. P7: official OpenCode adapter가 생기면 Mothership 아래로 넣을 수 있는지 먼저 확인한다.
